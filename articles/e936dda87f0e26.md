## active_record_doctor とは

active_record_doctor とは、Rails アプリのデータベーススキーマとモデルの定義を突き合わせて、設計上の不備を検出してくれる gem です。

「インデックスが張られていない外部キー」や「uniqueness バリデーションがあるのに DB 側にユニークインデックスがない」といった、動作はするけれど問題を抱えている箇所を指摘してくれます。

RuboCop がコードの書き方をチェックする gem だとすれば、active_record_doctor はデータベース周りの設計をチェックする gem というイメージです。

検出項目は「検出器（detector）」という単位で分かれており、2.0.1 では次の15種類が用意されています。

| 検出器 | 検出内容 |
| --- | --- |
| `extraneous_indexes` | 他のインデックスで代替できる不要なインデックス |
| `missing_foreign_keys` | 外部キー制約が張られていない外部キーらしきカラム |
| `unindexed_foreign_keys` | インデックスが張られていない外部キー |
| `missing_unique_indexes` | uniqueness バリデーションに対応する DB 制約がない |
| `missing_non_null_constraint` | 常に presence 検証されるのに NOT NULL 制約がない |
| `missing_presence_validation` | NOT NULL なのに presence バリデーションがない |
| `incorrect_boolean_presence_validation` | boolean カラムへの presence バリデーション |
| `incorrect_length_validation` | DB の桁数制限と length バリデーションの不一致 |
| `incorrect_dependent_option` | 不適切な `dependent` オプション |
| `mismatched_foreign_key_type` | 外部キーと参照先で型が異なる |
| `short_primary_key_type` | 主キーの整数型が小さい |
| `table_without_primary_key` | 主キーがないテーブル |
| `table_without_timestamps` | `created_at` / `updated_at` がないテーブル |
| `undefined_table_references` | 存在しないテーブル・ビューを参照しているモデル |
| `unindexed_deleted_at` | 論理削除カラムを条件に含めていないインデックス |

## 導入方法

Gemfile に追加します。

開発時にしか使わないので、development と test のグループに入れます。

```diff ruby:Gemfile
+ gem 'active_record_doctor', group: [:development, :test]
```

```bash
docker compose exec app bundle install
```

インストールすると rake タスクが追加されます。

```bash
docker compose exec app bundle exec rake -T | grep active_record_doctor
rake active_record_doctor                                             # Run all active_record_doctor detectors
rake active_record_doctor:extraneous_indexes                          # identify indexes that can be dropped without degrading performance
rake active_record_doctor:extraneous_indexes:help                     # Show help for extraneous_indexes
~ (省略) ~
rake active_record_doctor:unindexed_foreign_keys                      # detect unindexed foreign keys
rake active_record_doctor:unindexed_foreign_keys:help                 # Show help for unindexed_foreign_keys
```

検出器ごとに実行用のタスクと `:help` タスクが用意されています。

:::message
active_record_doctor は、モデルの定義を読み取るために実行前に `Rails.application.eager_load!` を呼びます。

そのため、ファイル名とクラス名が一致していないファイルがあると、検出結果が出る前にエラーで停止します。

その場合は `bundle exec rails zeitwerk:check` で不一致を確認できます。
:::

## 修正①：ユニークインデックスの欠落

まずはこの指摘です。

```
add a unique index on users(email) - validating uniqueness in User without an index can lead to duplicates
```

`User` モデルには `validates :email, uniqueness: true` が書かれているものの、DB 側にユニークインデックスがない、という指摘です。

これは「動いているから問題ない」と見過ごされがちですが、実害があります。

Rails の uniqueness バリデーションは、保存前に SELECT で重複を確認しているだけです。

同じ値を持つリクエストがほぼ同時に来ると、どちらも「重複なし」と判定されてしまい、結果として重複データが登録されます。

これを確実に防げるのは DB のユニークインデックスだけです。

マイグレーションを作成します。

```bash
docker compose exec app bundle exec rails g migration AddUniqueIndexToUsersEmail
```

```ruby:db/migrate/20260822112734_add_unique_index_to_users_email.rb
class AddUniqueIndexToUsersEmail < ActiveRecord::Migration[7.0]
  def change
    add_index :users, :email, unique: true
  end
end
```

```bash
docker compose exec app bundle exec rails db:migrate
== 20260822112734 AddUniqueIndexToUsersEmail: migrating =======================
-- add_index(:users, :email, {:unique=>true})
   -> 0.0057s
== 20260822112734 AddUniqueIndexToUsersEmail: migrated (0.0057s) ==============
```

再度検出器を実行します。

```bash
docker compose exec app bundle exec rake active_record_doctor:missing_unique_indexes
```

出力がなくなり、指摘が解消されたことが確認できました。

:::message
すでに重複データが存在する場合、ユニークインデックスの作成は `Duplicate entry` で失敗します。

その場合は、先に重複データを整理する必要があります。
:::

## 修正②：不要なインデックス

続いてこの指摘です。

```
remove the index index_comments_on_post_id from the table comments - queries should be able to use the following index instead: index_comments_on_post_id_and_created_at
```

`comments` テーブルには `post_id` 単体のインデックスと、`post_id` と `created_at` の複合インデックスの両方が張られていました。

複合インデックスは左端のカラムから順に部分的に使えるため、`(post_id, created_at)` のインデックスは `post_id` だけの検索にもそのまま使えます。

つまり `post_id` 単体のインデックスは完全に無駄になっており、検索性能を落とさずに削除できます。

インデックスは検索を速くする一方で、レコードの登録・更新のたびに更新コストがかかり、ストレージも消費します。

冒頭で触れた RDS の I/O の話とも繋がりますが、使われないインデックスは書き込み性能とストレージを削るだけの存在です。

なお MySQL では、外部キー制約のあるカラムには最低1つインデックスが必要です。

今回は `(post_id, created_at)` の複合インデックスが残るため削除できますが、代わりとなるインデックスがない場合は削除を拒否されます。

マイグレーションを作成します。

```bash
docker compose exec app bundle exec rails g migration RemoveExtraneousIndexFromComments
```

```ruby:db/migrate/20260822112856_remove_extraneous_index_from_comments.rb
class RemoveExtraneousIndexFromComments < ActiveRecord::Migration[7.0]
  def change
    remove_index :comments, :post_id
  end
end
```

```bash
docker compose exec app bundle exec rails db:migrate
== 20260822112856 RemoveExtraneousIndexFromComments: migrating ================
-- remove_index(:comments, :post_id)
   -> 0.0049s
== 20260822112856 RemoveExtraneousIndexFromComments: migrated (0.0049s) =======
```

こちらも指摘が解消されました。

## 対応するか判断が必要な指摘

検出された21件は、性質がそれぞれ異なりました。

### 存在しないテーブルへの参照

```
ActiveStorage::Blob references a non-existent table or view named active_storage_blobs
```

これは Active Storage や Action Text のモデルが Rails 本体に定義されている一方で、対応するマイグレーションを導入していないために出ている指摘です。

自分のアプリの問題ではないため、除外してしまって構いません。

### 提案どおりに直すべきとは限らないもの

`incorrect_dependent_option` は、次のような指摘です。

```
use `dependent: :delete_all` or similar on Post.comments - associated model Comment has no callbacks and can be deleted in bulk
```

`Comment` にはコールバックが定義されていないので、1件ずつ削除する `dependent: :destroy` ではなく、1クエリでまとめて削除できる `dependent: :delete_all` のほうが速い、という提案です。

たしかに削除は速くなりますが、`delete_all` はモデルを読み込まずに DELETE を発行するため、コールバックを一切実行しません。

後から `Comment` に `before_destroy` を追加したり、`has_many :attachments, dependent: :destroy` を足したりしたときに、それらが静かに無視されるようになります。

この検出器が見ているのは「現時点でコールバックがあるかどうか」だけなので、将来の変更まで含めて判断する必要があります。

今回は3件とも、指摘は理解したうえで対応を見送りました。

### 設定ファイルで除外する

除外はプロジェクトルートに `.active_record_doctor.rb` を置いて設定します。

```ruby:.active_record_doctor.rb
ActiveRecordDoctor.configure do
  # Rails 標準機能のモデルは、マイグレーションを導入していないため除外する
  detector :undefined_table_references,
    ignore_models: [
      "ActionMailbox::InboundEmail",
      "ActionText::RichText",
      "ActionText::EncryptedRichText",
      "ActiveStorage::Attachment",
      "ActiveStorage::Blob",
      "ActiveStorage::VariantRecord"
    ]

  # 対応の優先度が低いものはカラム単位で除外できる
  detector :incorrect_length_validation,
    ignore_attributes: [
      "User.name",
      "User.email"
    ]
end
```

`ignore_models` はモデル単位、`ignore_attributes` はカラム単位での除外です。

どのオプションが使えるかは検出器ごとに異なり、`:help` タスクで確認できます。

```bash
docker compose exec app bundle exec rake active_record_doctor:missing_unique_indexes:help
missing_unique_indexes - detect uniqueness validators not backed by a database constraint

Configuration options:
  - ignore_models (local and global) - models whose uniqueness validators should not be checked
  - ignore_columns (local only) - specific validators, written as Model(column1, column2, ...), that should not be checked
  - ignore_join_tables (local only) - join tables that should not be checked for existence of unique indexes
  - enabled (local only) - set to false to disable the detector altogether
```

`local and global` と書かれているオプションは、`global :ignore_models, [...]` の形式ですべての検出器にまとめて適用することもできます。

最終的に、21件あった指摘は11件まで減りました。

| `undefined_table_references` | 6 | 0 |
| `incorrect_dependent_option` | 3 | 3 |
| `missing_presence_validation` | 3 | 3 |
| `extraneous_indexes` | 1 | 0 |
| `missing_unique_indexes` | 1 | 0 |

残った11件も、内容を確認したうえで「対応する」「見送る」「除外する」を判断していけば、少しずつ減らしていけます。

いきなりゼロを目指すのではなく、実害の大きい検出器から潰していくのが現実的だと感じました。
